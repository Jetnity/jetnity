## Independently verified root cause

`run.mjs` creates the private HOME itself with:

`mkdtempSync(join(tmpdir(), ...))`

On macOS, `tmpdir()` commonly returns a visible path rooted at `/var/folders/...`, while `realpathSync()` canonicalizes the same filesystem location through the system alias to `/private/var/folders/...`.

Current `assertLocalNonSymlinkDirectory()` requires:
`realpathSync(resolved) === resolved`

That is appropriate for untrusted source material such as the user's original HOME / source npm cache, but too strict for the run-owned private HOME that the harness just created. It treats the macOS `/var -> /private/var` canonical alias as an escape.

## Goal

Accept canonical-path equivalence for the harness-created private HOME and its run-owned descendants without weakening source-cache trust boundaries or allowing symlink traversal inside the run-owned tree.

## Required design

### 1. Preserve strict source checks
Do NOT weaken these for:
- original user HOME;
- source `~/.npm/_cacache`;
- explicit source cache override.

They must remain:
- local absolute path only;
- visible final entry non-symlink;
- directory;
- source path under original HOME;
- nested symlinks refused;
- real path must not escape original HOME.

### 2. Separate run-owned private-HOME trust function
Introduce a dedicated helper for the private run HOME, distinct from `assertLocalNonSymlinkDirectory()`.

It may accept visible != real path ONLY because:
- the private HOME already exists;
- the final private HOME entry itself is a real directory, not a symlink;
- it is supplied as the harness-owned private root;
- containment is checked against both its visible root and canonical real root.

Do not special-case the username or hard-code `/var` or `/private/var`.

### 3. Canonical containment contract
For any run-owned destination/cache path:
- first require lexical containment under the visible private HOME;
- derive the relative suffix from visible HOME;
- canonical root = `realpathSync(privateHome)`;
- existing path components below private HOME must not be symlinks;
- for existing path, its real path must equal the canonical-root + same relative suffix;
- for not-yet-existing destination descendants, the nearest existing ancestor must satisfy that same canonical relation before directories/files are created;
- after creation/copy, verify resulting entries remain under the canonical private root and are not symlinks.

The macOS ancestor alias above the private HOME may differ. Symlinks created *inside* the private HOME remain forbidden.

### 4. Environment consistency
The isolated child env may continue to expose the visible private HOME path generated by the run. Do not rewrite unrelated env paths globally.

`NPM_CONFIG_CACHE` may likewise remain visible-path based. Cache-seed validation must understand visible/canonical equivalence for this run-owned root.

Do not weaken the requirement that HOME/cache belong to this exact run-owned root.
