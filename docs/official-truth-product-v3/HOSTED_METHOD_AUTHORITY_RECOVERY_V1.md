This path exists only for a completely installed, exactly identified, unused package. Before selecting it, Root must separately prove all of the following on the exact current target:

1. Original committed installation identities are available and match the current private namespace, API namespace and reader role OIDs.
2. The complete exact PG1 prerequisite remains installed; current HMA1 metadata, owners, bodies, function signatures/security/configuration, columns, constraints, indexes, triggers, RLS, policies, ACLs, row/array types, dependency inventory and role restrictions match the candidate.
3. The only incident reader membership is the actual PostgreSQL17 automatic edge, with member equal to resolved current postgres, grantorOID10/SUPERUSER, ADMIN=true, SET=false and INHERIT=false. There is no additional grant, setting, default or owned object for the reader.

5. No consumer, signed/operational work or publication depends on the new package. Known official_v3_ namespaces and ot_v3_ roles beyond this package are absent.

The SQL requires the acknowledgment context value root-verified-unused-quiescent-v1 in jetnity.hma1_recovery_context and the retained original OIDs in jetnity.hma1_recovery_private_oid, jetnity.hma1_recovery_api_oid and jetnity.hma1_recovery_reader_oid. Never derive a new acknowledgment merely from the current objects and call it the original installation identity.

The recovery repeats the exact installation creator and complete PG1 validators. It then binds the three OIDs/context, refuses known later V3 namespaces/roles, and runs the exact same MA1 structure and supplementary identity blocks as installation. It takes ACCESS EXCLUSIVE NOWAIT on all three history tables, refuses any history, and retains those locks through commit.

The drop order removes the five API functions and locked-current private function; all three empty tables together using RESTRICT; the remaining four private functions; the two schemas using RESTRICT; and finally the exact unused reader using ordinary DROP ROLE. PostgreSQL's supported role deletion handles that role's own automatic membership. There is no explicit bootstrap-grant revocation, CASCADE, unrelated role/membership cleanup, or deletion of PG1/platform/foreign objects.

pg_depend and DROP RESTRICT are useful last checks but cannot enumerate textual PL/pgSQL consumers. Extra GUC values, names, schema comments or a successfully executed dependency check cannot replace Root's current external consumer/quiescence proof. Any uncertainty stops this path.
