## Selected boundaries

M04 is a dormant private adapter for existing Rule and Discovery research queues, immutable command/audit records, start reservations and bounded S1 result references. It does not publish Accepted/version/cache state, qualify real sources, run a provider/scheduler, install hosted data or approve the method. The only proposed existing-code extension is the finite joint-factory bridge in MA1 authority-postgres.ts and its tests, subject to Root's later freeze.

## Identity and conservative uncertainty

The stable subject uses the existing semantic context normalisation plus kind/fact/method identity, with the full canonical preimage retained; the hash is a locator. New cycle/job/enqueue/claim/lease IDs, missing/recheck reasons, support metadata and MA1 epochs cannot hide any older unknown execution. Original full context remains bound to each job and result. A real hash/preimage collision refuses; it does not allocate a second subject bucket.

START_RESERVED commits before a producer can run. Only the actually acknowledged original winner receives a one-use private start permission. A recovered reservation does not mint permission. PREPARED binds full metadata and actual S1 evidence to the original claim/fence. Original valid fence can finish; new/expired fence cannot transfer or redispatch. Atomic original completion records successful settlement. Known failure requires actual producer-subtree termination, actual owned native drain and no ambiguous commit, then joint SETTLED_FAILURE plus exact Queue-Fail. A crash before that disposition stays unknown. No TTL, latest-only scan, retry count or later success erases unknown history.

## Owned invocation and command custody

Each outward call gets private immutable original command custody. Enqueue/claim inputs are detached before the unchanged coordinators; complete/fail commands are derived exactly from the observed original fence and private result/failure custody. A stored original execution envelope is not reconstructed using a later clock. QueueCommit callbacks/booleans/hashes cannot substitute real MA1 approval.

The private outer scope registers actual MA1/S1/M04 executor promises before acquisition or dispatch. Generic I1/worker/integration races are unchanged. On expiry/abort the outer scope seals admission, aborts and joins every admitted native child before settling. A separately sealed execution-processing subtree (delivery plus S1/I1 and all evidence/history callbacks) drains before a final known-failure transaction; that transaction is itself owned by the outer scope, never awaited by its own prerequisite. External callbacks receive no native handle or raw SQL capability. Their promise settlement is not proof that arbitrary hidden native/provider work ended.

### Native identity and wire admission

The application-side Enqueue entry first uses the actual unchanged S0 readers. The native M04 protocol accepts only already-normalised, closed S0 DTOs. It does not promise SQL `upper`/`trim` parity with JavaScript Unicode normalisation of raw country aliases. All admitted normal-form context, research, job, command and index strings are closed ASCII codes/enums/identifiers/dates; all numbers are bounded nonnegative integers. Original S1 proposal bytes are a separate transport, never reconstructed with this codec.

The native request is canonical JSON **text**, not an already lossy caller-supplied JSONB parameter. Before conversion/dispatch, recursively reject duplicate members in the `json` representation, unknown keys, forbidden identifiers, wrong scalar types, unsupported variants and bounds. After closed validation, a new finite canonical renderer must reproduce `schema2Kanonisch`: ASCII key ordering with `COLLATE "C"`, preserved array order, decimal integers and JSON string escaping. Require the submitted text to equal this freshly computed canonical wire text. Thus `-0`, exponent/decimal spellings, duplicate keys, escape aliases and noncanonical wire text cannot survive JSONB normalisation as another admitted request. This strict *native wire* is intentionally narrower than raw JavaScript S0 input; the public JS entry normalises raw inputs first.

For Rule identity, independently derive:

1. The source-free normalised scope returned by `regelScopeAusEvidenceScope(context.scope).scope`, including its complete closed nested fields.
2. Conditions: retain unconditional; sort the validated unique unresolved missing list; for specified conditions validate the full expression first, normalise with support, remove every atomic support list, normalise **again**, then embed the literal string `rule-applicability-structure:v2:` plus canonical expression JSON. Do not hash that expression string again or apply De Morgan/distributive rewrites.
3. The exact context preimage `{scope, route, conditions}`, adding both `contextRevision:2` and complete `application` only for a valid tagged context. No fallback dropping application restrictions.
4. `contextKey = official-truth-context:v3:SHA256(canonical(contextPreimage))`; the unchanged S0 job key is `research-job:v3:SHA256(canonical({contextKey,method,factKind}))`.
5. Retain and compare a complete semantic subject preimage `{kind:'rule_research',context:contextPreimage,method,factKind}` as well as the locator. Original complete cycle context, research reason and support remain separately retained in full job/command records. Neither support metadata, missing/recheck reason, job/cycle/operation IDs nor MA1 epoch enters this subject identity.

Discovery independently derives the unchanged key from canonical `{destinationCountryCode,citizenshipCountryCode,method}` and retains that full pair/method with `kind:'combination_discovery'`. Every native read/write recomputes identity from actual retained/input full context/action. A supplied subject preimage is compared with that computed value; it is never authoritative. Same locator/different full identity is collision/refusal, with no alternate bucket.

All 14 legacy predicate families plus 3 V2 additions are admitted, not a pilot subset. Before any expression normalisation: depth at most 4, total nodes at most 16, all/any operands 1–8. Support arrays have raw length at most 8, each `ev2_` plus 32 lower-hex digits; validate before stripping, dedupe/sort and omit empty support. Normalisation recursively flattens same-op groups, canonical-sorts/dedupes children, collapses singleton groups and eliminates double negation, then rechecks bounds. The second pass after support removal is mandatory. Numeric domains include age 0–120, group threshold 2–50, planned duration 1–3660 days or 1–120 months; months require unspecified counting. Country predicates use the pinned actual catalog. No arbitrary float, Unicode string or free-text predicate is admitted.

In each original, the `context` and `research` subtrees must already equal their normalised S0 values. This does not require compacting the enclosing JSON, changing its whitespace, or canonicalising source/URL/other proposal fields. Never rewrite original bytes. An otherwise valid but non-normalised context/research is a definite pre-effect `invalid_proposal` only after the actual producer promise ended; it may take the owned known-failure path once its subtree is sealed/drained and no write was ambiguous. ### Proposed fixed native operation boundary

One API function, `official_v3_jobs_api.execute_v1(text,text,integer,text,text,integer,integer,text) RETURNS jsonb`, receives canonical request text, method ID/revision/method digest/package digest/epoch, remaining native budget and absolute not-after. All arguments are required; CALLED ON NULL INPUT with explicit rejection, no default/variadic/overloaded entry. Only epoch may be NULL, exclusively for the strictly non-positive probe phase defined below; authorized phases require the real positive epoch. It is SECURITY DEFINER, owner `postgres`, VOLATILE, PARALLEL UNSAFE, `search_path=pg_catalog`. A closed discriminant admits only:

| Operation | Finite body / purpose |
| --- | --- |
| `queue_read` | Exact job key. Validate full stored job/subject; return present/absent, never a locator-only authority proof. |
| `queue_confirm` | Exact complete stable command. Reconcile the immutable original operation; no recomputed CAS envelope. |
| `queue_cas` | Complete stable command and actual `V3QueueCommit`; private disposition is regular, prepared completion, or owned terminal failure. Last two atomically append the exact execution disposition with queue command/audit/state. |
| `execution_read` | Exact original claim and a closed purpose `resume`, `lookup`, `confirm` or `artifact`; return only bounded state/job/result/S1-reference metadata. No original proposal or import decision body is stored in M04. |
| `execution_start` | Exact original claim plus full original leased record. Serialised all-history absence, actual current fence and MA1 epoch required. Only actual newly committed winner may receive a one-use start token. |
| `execution_prepare` | Exact claim, private winner token, complete bounded result metadata and full S1 references. Reopen/consume actual S1 evidence; same original live fence/epoch only. |

The native function does not expose a free method-check operation. Method/package arguments must bind the valid complete job operation and retained identity. The narrow runtime role does not receive MA1 reader/checker rights or S1 caller rights. A malformed/unknown variant cannot fall back to another operation.

Responses are finite per operation: valid present/committed/reserved/prepared/completed metadata, or explicit absent/collision/mismatch/blocked/quota/refused. Transport, timeout, codec and acknowledgement uncertainty map to non-positive unconfirmed/unavailable only after terminal native drain. Internal tokens never enter outward results or persisted logs. Row data alone is not a COMMIT acknowledgement.

### Physical records, blocker and limits — proposed

Use new private/API schemas owned by `postgres`, one new NOLOGIN/NOINHERIT/NOSUPERUSER/NOBYPASSRLS caller `ot_v3_jobs_caller`, and these seven private tables; exact columns/constraints are specified in the finite inventory below:

1. `slots_v1`: 1,024 preallocated numbered subject slots. Allocation locks one free row using SKIP LOCKED, not a global counter held by unrelated work. A slot may transition once from free to its exact subject, in the subject-creation transaction; never evict/reuse an occupied slot.
2. `subjects_v1`: stable job locator, complete semantic preimage, kind/method, slot, full current job and transactionally maintained counts/open-attempt pointer. Identity columns immutable.
3. `queue_operations_v1`: immutable global operation ID, subject, complete canonical stable command, command key, original complete CAS envelope/record/audit and authority binding. All successful commands, including deduplication, use this one ledger. A new-cycle job ID is globally unique over retained history; a reused historical ID refuses instead of replaying another cycle.
4. `execution_starts_v1`: immutable attempt locator, full original claim/claim command/leased job/fence/method+package+epoch and start token hash. Reserve before producer dispatch. Never return a token when reconstructing an existing row.
5. `execution_results_v1`: at most one immutable PREPARED index per start: complete Rule or Discovery worker result and 1–16 full S1 references, no original text or outcome body.
6. `execution_dispositions_v1`: at most one immutable known terminal disposition per start, tied by FK/unique identity to the exact queue operation: successful completion or known SETTLED_FAILURE plus matching Queue-Fail.
7. `catalog_binding_v1`: immutable installer receipt of the exact consumed S1/MA1 function identities/owners/security attributes/ACL/body fingerprints and expected M04 object inventory. It is not method/source authority or a hosted installation claim.

Proposed caps: 1,024 subjects; 256 successful queue operations and 64 starts per subject; one result/disposition per start; Rule exactly one S1 original, Discovery 1–16 unique originals; record and stable command each at most 65,536 UTF-8 bytes; aggregate native request/response at most 262,144 bytes, depth 24, nodes 32,768, with each embedded S0 record retaining its own depth16/nodes8192/bytes65536 limit. Full S1 read replies retain the predecessor's bound and are consumed individually, not returned as a giant M04 body. All counts are checked before staged mutation; exhaustion refuses without deleting evidence. These are dormant adapter technical bounds, not approved production capacity/SLO.

Every start without a disposition is unresolved, including PREPARED. The serialised subject check compares the pointer/counts against **all** immutable history (bounded by the subject cap), never only the latest row or a recent window. Pointer/history disagreement refuses; there is no repair or amnesty. New enqueue/claim/reclaim CAS refuses any unresolved history before changing attempts/revisions/audit. The only mutations allowed while the same original unresolved attempt exists are its valid preparation and atomic exact completion/known-failure disposition. Exact original claim replay is observation, not fresh claim CAS. Unrelated subjects use separate advisory/row/slot locks.

### Transaction order and final authority

For each operation use one real READ COMMITTED native transaction and exactly one fixed function call. No transaction spans a producer callback. The caller receives success only after actual COMMIT acknowledgement and terminal native cleanup; the public outer deadline is checked again after acknowledgement.

1. Before any catalog read or relation/advisory/row wait, capture the original statement timestamp and immutable native deadline as specified in R1-A02 below; check the remaining budget. Validate closed request/preimages and acquire the fixed M04 relation locks in documented table order with before/after-wait checks. No caller-selected relation/role/query or resetting the budget after a wait.
2. Compute all required advisory lock tokens (stable subject, operation/claim, new-cycle job ID, attempt and result identity as applicable), sort **actual signed bigint lock values**, dedupe collisions and acquire in that order. Hash collisions may serialize but never prove identity. Compare full canonical preimages under the locks. A cross-subject global operation collision cannot cause an ABBA inversion through inconsistent text order.
3. Lock actual subject, then its command/start/result/disposition rows in fixed identifier order. A new subject allocates one free preallocated slot under its subject lock. Verify full current cycle/fence, all older unresolved attempts, quotas, immutable command replay and index/history invariants.
4. Stage all needed M04 DML, immutable operation/audit/index/disposition rows and current-state/count changes. **All** unique, FK, check and trigger work is immediate/nondeferrable; no deferred user or constraint triggers. Their waits, including an operation ID reused by another subject, occur before the final authority call. A mismatch before mutation may return a definite no-effect status. A refusal after staging must throw and roll back the **entire** transaction; never catch only the last checker in a savepoint and commit earlier writes.
5. Read actual required S1 records in ascending operation ID (then full reference) order through the new fixed S1 definer bridge. The predecessor `read_v1` takes Operations FOR SHARE, so this is an explicit possible wait. Consume full original text, reference, outcome and audit; validate exact binding, digest/UTF-8 bytes, normalised original context/research and result semantics. Holding Operations FOR SHARE prevents concurrent S1 finish from changing that completion snapshot.
6. **Last:** call the actual MA1 checker through its SQL-standard parsed dependency bridge, taking the real method head FOR SHARE. After that wait sample fresh database clock; recheck exact package/revision/epoch, receipt-derived remaining budget, command not-after, and original lease where a new effect requires it. Any failure aborts all staged changes. Hold the method lock through COMMIT.
7. No further application DML, helper read, trigger/deferred constraint or uncontrolled query after that last check. Return the already constructed bounded response and commit. Intrinsic WAL/COMMIT/transport delay cannot be certified by an earlier timestamp; if the outer deadline expires or reply is lost, return unconfirmed after drain and reconcile only the original operation.

Actual S1 and MA1 functions are fixed prerequisites, not advisory callbacks. New helpers use SQL-standard `RETURN`/`BEGIN ATOMIC` bodies so `pg_depend` retains consumed real OID edges. The S1 read bridge is explicitly SECURITY DEFINER and owned by `ot_v3_intake_owner`, with fixed search_path. It alone obtains the existing S1 owner rights; M04 `postgres` receives only EXECUTE on this new helper plus necessary new-schema lookup, never grants on old S1 objects. The MA1 bridge is postgres-owned and consumes actual `require_current_locked_v1(text,integer,text,text,integer)`; no dead reference or STRICT/null bypass.

### Runtime lifetime and failure custody

There are four preallocated outer invocation lanes, fail-immediate on exhaustion, and separate finite native MA1/S1/M04 lanes. A scope reserves a registry entry synchronously **before** dispatch/acquisition and owns each actual terminal executor promise, combined abort listeners and cleanup. The old MA1 four-read/5,000 ms receipt rules remain unchanged. Its observer and actual read executor are joined; releasing a generic raced result never releases its native lane.

Native-capable dependencies allowed by this composition are exactly the code-owned fixed MA1 read, the four literal S1 statements (capture/read/reserve/finish), and the six fixed M04 operation variants. The S1 wrapper rejects any other string/arity/parameter shape before dispatch. Both `monitor/internal.ts` and I1 `boundedInvocation` remain unchanged races. Every actual S1 call made inside I1 is registered below them. An I1 facade `outcome_unknown`, unavailable reserve or ambiguous finish does not prove its internal run ended or a mutation did not commit.

Producer, source-evidence and history dependencies receive immutable DTOs and abort signals only; the registry is detached code-owned data. Every asynchronous evidence.inspect/evidence.reprove/history.read/history.reprove invocation is separately registered before dispatch in the bounded nonnative callback ledger, including calls still pending after an I1 facade race. They receive no SQL executor, pool, connection, role, method receipt consumer or queue-mutation capability. Positive tests use explicitly reviewed synthetic implementations that perform no hidden native/remote work. JavaScript cannot sandbox an arbitrary malicious callback: absence of hidden SQL and detached work is a **code-owned admission/source-review precondition**, enforced by the finite composition dependency inventory and import/transport guards, not inferred from a returned promise. Real providers/hidden external work are outside M04's guarantee.

Execution-processing sub-scope admission is separately sealable. A delivered pure producer promise ending does **not** seal it: capture/I1/preparation occur afterward inside that same execution scope. Known failure requires the actual delivery producer promise and every admitted evidence/history callback to have ended, every admitted native child in that execution subtree to be terminal, no late SQL admission possible, no ambiguous reservation/finish/commit, and a fixed non-sensitive reason. Only then may the private invocation mint one-use failure custody and admit the one subsequent joint failure-disposition transaction; that transaction is not part of its own prerequisite join, but is part of the outer drain. SQL itself cannot observe external producer termination. Its fixed private token/fence/command checks protect a trusted code-owned custodian assertion; an arbitrary failure string or a public DTO is not that assertion. The narrow database runtime role is therefore trusted to be driven only by this owned composition, never given to providers/application callers.

If a producer promise is uncooperative after abort, seal native admission, drain all already-owned native work, return non-positive, and leave START_RESERVED unresolved. Do not wait forever for it, claim external cancellation or free a producer slot while an admitted external callback remains unaccounted for; the finite poison/retirement rule is specified in the ownership map below. A process crash before producer start may remain conservatively blocked. Recovery cannot mint the original start token, transfer PREPARED to a new fence, or use a new MA1 epoch to settle an older unknown.

An already committed completion may be reconciled after its former lease expiry because no new queue effect is being granted. |
| SETTLED_FAILURE + matching queue failure | Exact original failure command may reconcile. Only a later explicitly valid new claim after existing backoff policy may reserve another start. |
| Older unknown with any newer history/index discrepancy | Refuse all new effects. No latest-row success, quota, age, reason/support variant or renewed MA1 receipt clears it. |

Every original attempt retains its original epoch. A freshly resolved receipt may reprove that **same** still-current epoch after the old five-second receipt expires; it does not replace the attempt epoch. Revoke/reapproval, even with identical package/method hashes, makes old PREPARED/unknown ineligible for positive continuation. Completed/failure history stays historically known; a new lawful cycle may use a new epoch only after there was already a known disposition. Cross-method-revision provider exactly-once is not promised.

`artifacts.resume` runs before the worker. It calls native execution_read with the full original claim, proves the stored subject, original claim journal/current cycle and all-history blocker. Completed returns only an actual direct succeeded successor plus real result/S1 evidence. Unknown returns unconfirmed before a claim. For same-original valid PREPARED, generic resume must return not_attempted (meaning no already-completed worker), but the lexical invocation is marked **prepared-only**: worker claim can only reconcile its original existing claim, result lookup must return that PREPARED, and execute/reserve paths are disabled. A missing PREPARED read then returns unconfirmed; it must never fall through to a producer. For genuinely absent execution, the generic worker may proceed, but claim/reclaim CAS and start reservation recheck under subject locks. Thus preflight races cannot consume an attempt or disturb an active producer.

**A01 — authoritative absence cannot become a free MA1 oracle.** The exact common native request shape is `{operation,phase,body}`, protocol V1 by the versioned function name; unknown fields refuse. `phase` is probe or authorized. Probe is legal only for queue_read, queue_confirm and execution_read and has NULL epoch; all other arguments are bounded, but probe never invokes the actual MA1 checker or emits positive data. All mutation phases and positive record/custody reads require authorized plus a real private receipt epoch. No method-status/epoch/package-state detail is returned by a probe.

| Operation | Exact body |
| --- | --- |
| queue_read | `{jobKey,continuation}` |
| queue_confirm | `{command,continuation}` |
| queue_cas | `{command,commit,subjectText,disposition}`; disposition is exactly `{kind:'regular'}`, `{kind:'completed',attemptKey}` or `{kind:'settled_failure',attemptKey,token}`. |
| execution_read | `{claim,purpose}` with purpose resume/lookup/confirm/artifact. |
| execution_start | `{claim,leasedJob,subjectText}` |
| execution_prepare | `{claim,attemptKey,token,result,references}` |

Under the same subject/operation serialization, the probe first locates the actual stable subject and examines **all older unresolved execution**, even if this particular new claim/operation ID has never existed. For internal queue reads/confirms during an already justified original completion/failure, `continuation` is exactly null, `{kind:'prepared',claim,attemptKey}`, or `{kind:'owned_failure',claim,attemptKey,token}`. The first non-null value is created only from private PREPARED custody; the second only after actual terminal/drain/no-ambiguity failure custody. SQL compares full original claim/current fence and sole unresolved attempt, plus actual PREPARED or winner-token/no-PREPARED respectively. Any **other** older unknown still blocks. This permits the matching original terminal command to reach its exact native CAS; it cannot permit a new claim/start. A missing terminal command may return fixed not_attempted as *command-ledger absence only* after that exact continuation check, independent of MA1; it is never evidence that execution is absent. That second transaction rechecks the full subject/history/command after its real locks; any now-negative absence/blocker still returns the same fixed negative without MA1, while actual positive data undergoes the final actual MA1 proof. **A02 — one original budget before every possible wait.** At private admission capture `D = min(outerDeadlineMonotonic, actual latest Held.deadline)` for authorized work, or min(outer, nowMono+5000) for a non-positive probe. Do not cache a later deadline from an earlier overlapping reproof; re-read latest Held immediately before admitted dispatch and shrink D. A registry/lane entry is reserved before acquisition and the original D is passed to the owned executor. Connection acquisition, BEGIN, fixed transaction timeout setup and main statement all use that same D; check before each action, and on expiry abort/join rather than starting another action. There is no fresh five-second budget after connection acquisition.

For the native wall-clock cap, at the actual terminal decoding point of each resolve/reprove, sample monotonic `b` **after** actual executor acquisition/read/cleanup has ended and after the existing original/shrunk `Held.deadline` has been calculated from the latest shared Held state. Set `r = floor(Held.deadline - b)`; nonpositive r supplies no companion authority. For a valid actual observation, derive `candidateDbCap = observedAt + r milliseconds`, additionally bounded by actual approvalUntil when finite, then `dbCap = min(previousDbCap if any, candidateDbCap)`. Never use observedAt+5000 or observedAt+remainingMs without subtracting actual acquisition/read/drain elapsed time. The actual observation occurred no later than terminal b, so this maps conservatively without assuming equal host/database clock offsets. On overlapping reproof, read the latest Held deadline only after its own terminal drain; neither old captured deadline nor a late reply may enlarge dbCap. This companion metadata is private beside the same WeakMap; it changes neither the old two-operation return values nor old Held monotonic semantics and is never an exported permit. Other receipts/resolve calls remain distinct and globally capacity-bounded. The two clocks provide independent conservative caps; no claim of exact host/database clock offset synchronisation or future COMMIT certification is made. The conversion assumes a normally advancing database wall clock over this bounded observation/effect interval; arbitrary clock jumps are not equivalent to a monotonic clock. Detected discontinuity/expiry/abort is non-positive after native drain and original-operation reconciliation, never a claim that a possible late commit did not happen.
