## 3. Technical fit – public evidence only

Wego is technically a strong fit for Jetnity's neutral Flight metasearch architecture:

- live airfares;
- one-way, round-trip and multi-city;
- trip with 1 / 2 / >2 legs maps naturally to Jetnity's ordered-leg truth;
- server-initiated search session;
- incremental polling/results;
- multiple fares from OTAs/airlines;
- backend OAuth/client-credentials posture;
- client-side filtering/sorting possible after results are received;
- booking continuation occurs through Wego deeplinks rather than Jetnity acting as merchant of record.

Published operational constraints include:

- real end-user searches only, not bots;
- only Wego deeplinks to Wego partners in Affiliate results;
- Search-to-Click >= 5%;
- default 50 Search calls/hour for a test key;
- default 500 Search calls/hour for a regular key;
- polling/results calls excluded from the published Search-call quota;
- limit can be raised if ratio is maintained and reduced if it is not.

These are provider terms/evidence, not Jetnity defaults.

## 5. Prepared project description – NOT TO SEND

### Concise English draft

> Jetnity is a Switzerland-first intelligent travel planning platform centered on one unified trip workspace. Travellers can structure a complete journey, understand missing travel components and compare relevant options without using isolated search tools. Jetnity's Flight layer is provider-neutral and supports one-way, round-trip and multi-city itineraries through ordered route legs. We are evaluating Wego's Affiliate Flights API as a potential live metasearch/referral source because its search-session and polling model can provide current fares from multiple travel providers while booking continues through provider deeplinks. Jetnity intends to preserve clear price/provider provenance and neutral recommendation logic; commercial commission must not determine which option Jetnity recommends. Before any integration, we need to confirm the applicable API commercial, privacy, data-use, attribution, cache/persistence and Swiss-market terms.

This is preparation only and must not be sent while the Legal/Privacy Hold remains.

## 6. Legal / privacy questions that must be resolved before `A-WEGO`

### User/customer and data ownership

1. How does Affiliate Terms section 4.4 apply when Jetnity uses the Affiliate API inside Jetnity's own trip-planning UI rather than sending a user first to a Wego Site?
2. Precisely which information is considered “generated by” a referred user and owned by Wego?
3. Does that include search route, dates, passengers, locale, currency, device/app type, IP/network metadata, Wego search IDs, click identifiers or any Jetnity account identifier?
4. Does Wego expect Jetnity to send any stable user/account identifier? Jetnity should avoid this unless strictly necessary and legally approved.
5. Are Jetnity and Wego independent controllers, joint controllers, controller/processor or another relationship for Affiliate API search data?
6. Is a DPA / data sharing agreement available for Switzerland and EEA users?
7. What legal basis does Wego rely on for data obtained through Affiliate API searches?
8. What privacy notice/disclosure must Jetnity show before a search is sent to Wego?
9. Are cookies/device identifiers set or required in a pure API integration? If yes, what identifiers, purpose and lifetime?
10. The public Affiliate Terms describe a 30-day referral cookie for subsequent Wego visits. How does that operate for API-generated Wego deeplinks and what consent/disclosure is expected?
11. What retention/deletion/export rights and duties apply to API search/session/click data?
12. Which data regions, subprocessors and international-transfer mechanisms apply to Swiss/EEA users?
13. What security incident and data-subject-request cooperation duties apply?

### Contract hierarchy and termination

14. Which additional API Agreement/terms apply to the Affiliate API and when will Jetnity receive them?
15. Which provisions of the general Affiliate Terms are superseded by the API Agreement?
16. Does the one-year term / automatic one-year renewal apply to the API relationship?
17. Is termination only available by notice at least 30 days before the term end, or do API-specific terms provide convenience termination?
18. What happens to cached/persisted Wego-derived data and attribution records at termination?
19. Is any API fee refundable if production access is withdrawn, suspended or commercially unsuitable?
