## M2 — durable custody and transaction ownership

`prepareOriginals` verifies the existing complete closure and synchronously owns every byte before the first await. It checks strict UTF8, full-body fingerprint and exact support count. The producer calls the **existing** integrated publisher and new binding function in one PostgreSQL transaction. The binding checks the whole retained SQL closure, protected review packet, ordered Evidence identities/raw digests, exact admission, original conflict, validity, expiry, freshness and current lifecycle. Every original/ciphertext/support/Rule binding/event rolls back with the eight global provenance tables on failure; a separately committed review preauthorization is not an accepted Rule.

Success requires acknowledged COMMIT and a fresh reader connection. Lost COMMIT acknowledgement returns `commit_outcome_unknown`; it cannot create a success receipt. An explicit `verify_existing` retry re-proves stored originals and exact bytes without new rows or healing missing bytes. This is durable record/closure readback, not a backend PID/XID receipt. The native lost-ACK test models acknowledgement loss after a real idempotent COMMIT; the existing transport's broader COMMIT/deadline/race proof also remains in the full suite.

The low-level publisher/binder results remain provisional. Only the owning producer returns the sanitized post-COMMIT result. No raw original, encryption key or accepted DTO is returned by that high-level result.

## M4 — current lifecycle, expiry and restore quarantine

Events are append-only, contiguous, hash-linked and bounded. Source/profile withdrawal, Rule withdrawal/conflict/supersession, acceptance, expiry and disposal advance a locked monotonic head. Profile withdrawals bind the exact profile version. The reader checks every event link/count/hash against both head and independently supplied witness. Missing/gapped/extra/unavailable state, stale witness or a heartbeat older than 60 seconds refuses. Only the lifecycle role may checkpoint the exact independently held sequence/hash; it cannot checkpoint a mismatching restored head.

The current guard transaction must use READ COMMITTED and holds a SHARE lock on the lifecycle head through original re-proof. The historical provenance reader retains its existing REPEATABLE READ / READ ONLY contract on a separate owned connection while that guard remains open. All authorized original disposal and lifecycle writes need the conflicting head lock. This combines current lifecycle serialization with the unchanged historical reader; it does not weaken that reader's transaction guard. The low-level read helper requires the caller's open guard transaction; the owning post-COMMIT producer enforces it. Authority is as of that guarded read, never an indefinitely reusable positive result.

Expiry automatically refuses reads before any sweep. The protected sweep first appends affected Rule expiry, then disposal, then deletes ciphertext in the same transaction. Original/review metadata survives, explicitly unable to prove missing bytes. A failed sweep rolls back both events and deletion. Retry cannot replace missing original bytes, refresh old deadlines, or resurrect withdrawn/expired data. Safe refresh means a newly reviewed receipt/Evidence/origin version; old snapshots are never rewritten. The legacy current-claim projection/refresh adapter is not implemented here.

The **local** witness is held outside the database by the test/producer context. A durable independent production witness, key custody/rotation, backup/PITR/WAL/replica/export inventory and restore quarantine/runbook remain unimplemented hosting prerequisites. Reading a restored DB cursor and calling it an independent witness is forbidden. Local tests demonstrate refusal against the held later witness and expiry; they are not a hosted restore drill or residual-copy SLA.
