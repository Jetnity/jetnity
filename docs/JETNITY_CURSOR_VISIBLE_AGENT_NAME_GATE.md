# Jetnity – Visible Cursor Agent Name Gate

Stand: 28. August 2026  
Status: **Product-Owner-verbindliche Continuity-/Agentenregel**

## Zweck

Der logisch vom Technical Lead vergebene Cursor-Agentenname muss nicht nur in Task, Status, Handoff, Self-Review und PR-Kommunikation stehen. **Der tatsächlich sichtbare Cursor-Agent-/Session-Name soll exakt diesem Namen entsprechen.**

Diese Regel präzisiert den bestehenden Technical-Lead-/Cursor-Operating-Standard nach Product-Owner-Evidence vom 28. August 2026.

## Verbindliche Regel

1. Vor jedem neuen Cursor-Agentenstart vergibt der Technical Lead einen **exakten Anzeigenamen**.
2. Dieser exakte Name wird als erste und dominante Benennungsanweisung im Cursor-Startauftrag wiederholt.
3. Wenn der Cursor-Startpfad oder die Session eine Rename-/Title-Fähigkeit anbietet, muss der Agent sie verwenden und den sichtbaren Namen exakt setzen.
4. Die Agentenbenennung gilt erst dann als vollständig erfüllt, wenn die verfügbare Session-/UI-Evidence keinen abweichenden sichtbaren Namen zeigt.
5. Ein intern korrekt dokumentierter Name bei gleichzeitig abweichendem sichtbaren Cursor-Namen ist **nicht** vollständig erfüllt.
6. Wenn die gestartete Session vor materieller Arbeit sichtbar falsch benannt ist und sich nicht umbenennen lässt, darf sie nicht still unter dem falschen Namen als reguläre Generation weiterlaufen. Der Technical Lead muss den Startpfad korrigieren bzw. die Session kontrolliert neu anstoßen.
7. Ein fehlgeschlagener reiner Startversuch ohne materielle Arbeit gilt nicht als abgeschlossene Agenten-Generation. Der bereits zugewiesene logische Name darf für den korrigierten Start beibehalten werden; es wird keine künstliche neue Generation erfunden.
8. Bei unmittelbaren Review-Fixes desselben Slices bleibt derselbe exakte Agentenname erhalten.
9. Cursor-Agenten dürfen niemals behaupten, die sichtbare UI sei korrekt umbenannt, wenn dafür keine Evidence vorliegt.

## Evidence

Mindestens eine der folgenden verfügbaren Quellen soll den sichtbaren Namen belegen:

- Cursor-App-/Session-Evidence,
- Cursor-Agent-Link/Run-Evidence mit eindeutigem Titel,
- andere direkt verfügbare Cursor-UI-Evidence.

Repository-/PR-Text bleibt wichtig, ersetzt aber bei einer ausdrücklich verlangten sichtbaren Benennung nicht die sichtbare Session-Evidence.

## Continuity

Diese Regel ist bei jedem neuen Cursor-Agentenstart zu berücksichtigen. Ein neuer Chat darf nicht zu der älteren schwächeren Interpretation zurückfallen, nach der ein abweichender sichtbarer Name akzeptabel wäre, solange nur das Repository den logischen Namen korrekt führt.
